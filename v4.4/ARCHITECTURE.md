# v4.4 设计与对照

## P6 症状和改动

| P6 原始证据 | 对应实现 |
|---|---|
| reader 数据寄存器到 X SRAM D[6] 保持 −0.14004014 ns，W/Y 和 TCM 等路径同类 | X/W/Y 的使能、地址和写数据在下降沿锁存，宏仍在上升沿读写。读有效和输出页选择与同一请求对齐。 |
| E203 DTCM 到 reader 地址寄存器建立仅 +0.00008583 ns | 整机通过 System Bus 下发命令，DMA 直达共享 SRAM。请求和应答均入队，切开 DTCM/仲裁到 reader 的同拍路径。 |
| MAC 内旧部分乘法的建立几乎为零 | 16×16 乘法按四个 8 位分块并行，分别寄存部分积、交叉项和低位进位。每拍仍可接收一对操作数，流水延长一拍。 |
| TCM 与外部复位也有保持违例 | TCM 使用请求队列加半周期宏输入级。外部复位沿用 P7 异步拉低、下降沿释放。 |
| v4.4 r3 主组合的 GPIO B 与 AON 输出过快 | r4 用工艺库的反相器对给短输出增加延迟。按原约束重新提取互连并同时检查建立和保持，`output_hold_eco.tsv` 记录每个端口的变化。 |
| v4.4 r4 在 SS/CMAX 门级回标中丢失首笔 ITCM 写入 | r5 用常开时钟驱动 ITCM/DTCM 控制器接收端与队列，保留宏的 `ram_cs` 门控。只改两路 TCM 控制器时钟，CPU 执行单元仍按原方式门控。 |

ITCM 保留最后一个已交付的取指字。FIFO 空后会移动读指针，而 E203 在 holdup 有效期间可以复用这个取指字。独立随机 ITCM 测试、跨边界取指和真实 ROM 启动都必须验证该契约。

ITCM 的 ready 必须表示当前时钟周期确实能接收命令。r4 门级对照中，上层已看到有效握手，但 ITCM 控制器的接收时钟没起跳。r5 从原始 E203 文件生成两处时钟连接替换，源 SHA 和生成源都进入证据清单。宏按请求开钟，控制器保持可接收。待机功耗需用新版活动重新测量。

## 通路与计时

E203 和下载口分别接到既有 ICB 仲裁器。DMA 成为第三个主端。请求经命令 FIFO 和下降沿保持后到达同一个物理共享 SRAM，返回数据经应答 FIFO 按命令顺序回到各主端。DMA 共有四个信用，覆盖已接收的内部请求、已发送的总线命令及尚未消费的应答。reader 对四个解码流各自预留缓存空间，并按 FIFO 中的流号分发应答。writer 在收到全部写应答后才完成任务。

仍按 12 个冷任务计时。起点是外部端口开始写输入和参数，终点是最后一次结果写响应。TB 逐项验证结果字和输出区哨兵，分别记录装载、CPU 调度、DMA/计算阶段。对比同一 TB 的串行全槽位和流水全槽位。只装载有效码流的实验单列，等待评测装载接口确认。源码与同一组编译文件的证据绑定，建立和保持均在原 150 MHz 约束下判定。

基线来自队友分支提交 5530ae66，P6 原始报告位于服务器个人目录的 soc_20261107/astra_runs/astra_p6r1_20261108_180156_138277。P6 的 12 次任务共 1,617,436 拍，NICE 窗口 818,333 拍，共 76,181 读和 58,547 写。核心算子、数据格式与 testbench 期望沿用 v4.3。
