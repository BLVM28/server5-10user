# 怎样调试语音数据、RTL 和 E203

目标是把错误分层定位：**先确认提取的模型输入正确，再证明整数算法精度，再证明 RTL 逐位一致，最后证明 CPU/内存/驱动真的能调用它。** 直接从最终 yes/no 是否正确反推 RTL 错在哪里，信息太少。

## 1. 三组对照必须同时存在

```text
指定浮点 KWT 模型 ──截取 Dense1 的 X/W/b/Y_float──┐
                                               │ NRMSE ≤3%
X/W/b 编码 ──整数金模 numeric_model.py── Y_int ──解码┘
       └──相同整数输入 → RTL/真实 E203 → Y_rtl ──逐位等于 Y_int
```

若 `Y_rtl != Y_int`，先修硬件/搬运/编码，不能调整量化尺度掩盖它。若整数比对相同但浮点误差超标，问题在数值格式或输入提取，不是把 TB 期望值换成 RTL 输出。若上述都通过但 CPU 运行失败，查地址/固件/接口，别先改 MAC。

## 2. 从已有数据开始：不需要先下载完整语音集

当前 `v2/vec/` 是可重跑的整数回归向量；`vec/weights/` 含指定 checkpoint 导出的 12 套第一 Dense 参数；`vec/activation_smoke/` 是静音和合成音调的模型流程检查。

本地 PowerShell，在项目根运行：

```powershell
# 当前已安装 Vivado 2023.2；脚本默认 D:/vivado/Vivado/2023.2/bin
python v2/py/run_xsim.py --tag learn_arith --tops tb_kwt_arithmetic
python v2/py/run_xsim.py --tag learn_system --tops tb_kwt_icb tb_kwt_system
python v2/py/run_xsim.py --tag learn_v2 --tops tb_kwt_overlap tb_kwt_mul_pipeline
python v2/py/run_xsim.py --tag learn_activation --tops tb_kwt_system --vectors v2/vec/activation_smoke/rtl
```

分别看 `ALL PASS` 的完整计数、`build/<tag>/results.json` 和失败日志。工具退出码为 0 不够，脚本还检查 PASS 和 fatal。`29/29` 是场景数，不是 29 条语音或 29 层；系统 TB 检查完整矩阵、错误、背压和复位，但其 CPU 是请求激励、内存是行为模型。

优先用新 `--tag`，避免覆盖自己正在分析的旧日志。归档后的 `build/` 会被脚本正常重新生成。只运行上面的仿真不需要重新生成固定向量；`make_vectors.py` 会写 `vec/`，不要为了“试跑”覆盖现有基准。

## 3. 真正的语音数值调试

### 3.1 准备正确样本，而不是训练新模型

1. 获取赛题指定 Google Speech Commands V2（`speech_commands_v0.02`）。本工作区尚未准备完整真实数据集；上游 README 的 Setup 是数据入口。
2. 按指定源码划分 training/validation/testing、映射十个目标词及 unknown，按规定生成全零静音。参考 `kws_streaming/data/input_data.py:81–125,235–309` 的划分和索引逻辑；不要仅靠文件夹名称或手写 split 标签假定合法。
3. training 可用于无梯度数值标定；validation 用于调试；testing 不用于改尺度、阈值、权重或数值配置。禁止重新训练、微调和蒸馏。
4. 保持原模型推理模式，关闭 Dropout/随机增强；不得用自己的 MFCC 实现替换指定预处理后仍声称同一参考。

现有 `capture_activations.py --manifest` 接受 WAV 清单，但**只检查你写的 split 是否是 training/validation，并不自动证明真实划分正确**，也不会自动完成官方类别抽样。当前 WAV 读取仅接受 16 kHz、单声道、16-bit PCM、长度 ≤16000，短音频补零；更长/不同格式输入需要先按指定流程规范化，不能随意裁剪重采样。

### 3.2 运行原模型并截取 12 层 Dense1

本地已保留可用 Python3.8 + TensorFlow2.4.0 + Addons0.12.1 环境。安装缓存清理不会删除这个环境，**不要直接移动 `tf24_env` 或 `python_runtimes`**，其路径有依赖。

以下为可运行的 smoke 命令，不会修改冻结向量；新输出放新目录：

```powershell
& './03_过程与分析/05_工具/tf24_env/Scripts/python.exe' -B v2/py/capture_activations.py --smoke --out v2/build/learn_model_smoke
```

真实清单示例（路径是示意，必须换为实际 WAV；相对路径以清单所在目录为基准）：

```json
[
  {"path":"speech_commands/yes/actual_clip.wav", "split":"validation", "label":"yes"}
]
```

```powershell
& './03_过程与分析/05_工具/tf24_env/Scripts/python.exe' -B v2/py/capture_activations.py --manifest path/to/verified_validation_manifest.json --out v2/build/validation_capture
```

脚本用同一批原始层对象重放 PostNorm，逐样本确认最终 logits 与原模型普通调用逐位相同，防止截取错节点；再比较 Dense1 定点金模与浮点参考。它不训练模型，也不把硬件结果塞回原模型作为本次浮点参考。

当前脚本的验收输出是 Dense1 的误差和饱和统计；它没有计算整份语音集的分类准确率，manifest 中的 label 也不能自动证明分类正确。若做额外分类演示，应另记录原模型预测、真实标签和完整推理链路，同时保留本科要求的逐层 NRMSE。

看 `report.json`：

| 字段 | 意义 / 判断 |
|---|---|
| `checkpoint_existing_objects_matched`、`all_dense1_weights_equal_export` | 权重加载和导出一致性；失败应停下来核对版本 |
| `capture_method` | 同原层对象重放、最终 logits 相等；不是随手模拟一套“近似模型” |
| `samples` | 样本清单和文件 SHA；核对划分/类别/来源 |
| `layers[i].error_sum_sq/reference_sum_sq/elements` | 正确聚合逐层 NRMSE 的原始统计，合并样本应加这些量 |
| `x_saturated/y_saturated/w_saturated/b_saturated` | 哪个位置丢动态范围；不能只看平均误差 |
| `max_layer_nrmse` | 单位是比例：0.03=3%，不要再次把 3 当门槛 |

**当前脚本的重要限制：** 对清单所有样本做数值统计，但只把第一个样本的 12 层转换成 `rtl/*.hex`。因此运行一次系统 TB 并不覆盖清单全部语音。需要 RTL 覆盖多条样本时，可把每条样本单独放一个清单、输出到不同目录逐条运行；以后再扩展多样本导出器。冻结后 12 个性能任务必须保留各任务单独误差，目前汇总 report 不能代替逐任务门槛检查。

### 3.3 用真实激活验证 RTL

```powershell
python v2/py/run_xsim.py --tag validation_first --tops tb_kwt_system --vectors v2/build/validation_capture/rtl
```

TB 会装入该目录的 12 层 X/W/b、核对 Y/40 位累加结果；这里仍是独立核仿真。另应核对浮点统计与该样本自己的 NRMSE。发现第一个错误时记录 `(sample, layer, m, n, k)`、输入整数、完整 acc、量化值和目标地址，不要只保存最后一个 PASS/FAIL。

## 4. 在新虚拟机里怎么用

在 VMware RHEL7 终端：

```bash
cd /home/eda/kwt_vm_20261101
make -C flow check              # 核对已完成证据与哈希，不重跑 EDA
make -C flow functional-v2      # 完整 RTL 功能回归，旧结果归档
make -C flow v2                 # 功能 → 综合 → 双角 STA/ECO → 双角门级 → 汇总
make -C flow -j2 all            # 两版独立执行，适合做同条件比较
```

这些命令是 **Linux 命令**，不能直接在 Windows 项目目录套用。Windows 的 `vm_eda/` 对应 VM 的 `flow/`；本地 `v2/` 对应 VM 的 `work/v2/`。修改本地代码后必须同步相应源码、TB、脚本、向量并核对 SHA，VM 不会自动看到 Windows 改动。

当前 flow 会读取已安装工具和库，不修改安装。Xcelium 做完整加速器 RTL 功能；Genus/Tempus 仅对无 SRAM 依赖的 dot64 做 GPDK045 实现；不能拿这个结果替代 SMIC40 整核。最终检查目录是 `sta_eco_*` 和 `gate_eco_*`；`sta_slow/fast` 是修复前的失败基线。

VM 仿真库对负单限 recovery 的表达有限，因此保留原 SDF，仿真另用仅把负检查限收紧为零的兼容 SDF。须同时看 `sdf_compatibility_audit.json` 和门级 `results.json`，不能只看 32/32 功能值相同。

## 5. 真 E203 最小接入路线

### 5.1 先解决平台身份与共享 RAM

当前仅核对历史公共 ZIP 的实际接口，未确认它就是 2026 正式平台；所见 `e203_soc_top.v:135–178` 的 sysmem 是读零占位。需要正式工程/允许修改的私有副本，确认：

| 必须确认 | 为什么挡住整机验收 | 不同时怎样改 |
|---|---|---|
| CPU/RTL filelist、`E203_HAS_NICE`、正式头文件 | 同名 demo 与本方包装不能同时编译 | 在私有工程移除 demo，加入本方包装和 10 RTL；接口变化则调整包装 |
| 512 KiB RAM 实体、译码、基址/保留区、NICE LSU 可达性 | 地址像 RAM 并不意味着真的有存储 | 接真实存储/互连，再定义 `KWT_MEM_BASE/BYTES`；分散窗口需扩展校验 |
| 时钟、复位域、写应答语义 | 防止旧应答串任务或 CPU 提前读结果 | 共同复位，或增加隔离/排空；必要时补写可见性机制 |
| cache/一致性及自定义指令分配 | fence 不能代替 cache 清理；ABI 可能冲突 | 非缓存共享区或平台 flush/invalidate；同步修改指令与驱动 |
| 错误异常路径 | `nice_rsp_err` 可能使 CPU trap | 编写/验证 trap 处理，不能一律按 C 函数返回错误码 |

这些缺口在现有取证和事实基线中明确记录；本轮整理没有凭未更新的服务器文件声称它们已经解决。

### 5.2 固件和存储应当怎样配合

`kwt_driver.h` 只有描述符、pack 函数、指令封装，**不是完整 BSP/固件**。还要正式平台的启动代码、链接脚本、栈/程序区、异常处理、数据装载和结果导出。

建议测试顺序：

1. CPU 先启动最小固件，能记录成功/异常。CPU 对正式共享 RAM 做写回读和边界测试，排除读零占位。
2. 确认同一 RAM 可由 NICE 访存路径访问；检查实际字序和 byte address，不能仅 CPU 读写成功就认为加速器也能访问。
3. 分配互不重叠的描述符/X/W/b/Y。下面是**相对已确认区域起点的示例布局，不是平台地址**：desc=0、X=32、W=12704、b=45472、Y=46496，总长 97184 B；还要避开程序、栈及平台保留区。
4. 参数加载环境/CPU 把整数数据写入该区域；设置 layer、magic、format。CPU `.insn` 的 rs1 放描述符地址。
5. `kwt_run()` 发出长指令，CPU 等响应；硬件自行读数据、计算、写回，CPU 不代算 Dense1。
6. CPU 收到成功后按平台一致性要求读出 Y，与同一整数金模逐位比较；错误时丢弃 Y，并检查 trap/错误记录。
7. 先跑一层，再不复位连续换 12 层参数；加入总线背压、地址错误、读写错误、合法域复位，并确认失败后下一任务可恢复。
8. 在完整 SoC TB 中计时，从输入/参数开始装载到最终写回，包含 E203 调度；不能直接抄独立核 `core_cycles` 作正式吞吐。

候选指令 ABI：opcode=0x7b、funct7=0x40、funct3=110、rs2=x0；描述符 8 个 32 位字。实际 rd/rs1 寄存器由编译器决定，历史反汇编 `0x8005657b` 只是当时 rd=rs1=a0 的例子，不应把它当通用固定机器码写死。

### 5.3 “已服务 E203”的最小证据

需要真实 E203 执行固件产生 NICE 请求的波形/日志，真实 RAM 中完整 Y 与金模一致，全部写响应在 CPU 完成之前，无遗漏异常；并记录平台版本、编译宏、filelist、ELF/源码哈希及计时窗口。仅有接口端口编译通过、GCC 生成 `.insn`、BFM 请求或同名包装回归都不足以单独证明这一点。

## 6. 看到症状先查哪一层

| 症状 | 首先检查 | 证据/信号 |
|---|---|---|
| 输出整体放大/缩小固定倍数 | F 位数、解码 /2048、W 的 F=16、bias 的 F=27 | numeric_model、输入编码、完整 acc |
| 正数对、负数错或 tie 错 | signed 扩展、部分积高/低字、RNE | arithmetic/mul_pipeline TB |
| 每两个元素交换 | 半字装配 PACK_LOW_FIRST | x/w/y HEX 与 ICB wdata[15:0] |
| 每 8 列错、换列组错 | group/lane/W 地址跨度 | W_base+512*k+16*g+4*j |
| SRAM bank 边界或最后 k 错 | 同步读 valid/bank 对齐、last 排空 | x_rv/w_rv、issue_k、mul_last |
| 总线一慢就错 | 命令保持、等写应答、y_hold/MAC 两槽 | icb TB、overlap TB、Y_REQ/Y_WAIT |
| CPU 不返回 | 是否真发出指令、cmd/rsp 是否握手、RAM 是否响应、trap | nice_req/ICB/nice_rsp 与 CPU PC |
| 返回/异常 0x11 | 合法窗口仍为 0、描述符地址不对齐/越界 | KWT_MEM_BASE/BYTES；不要直接绕过检查 |
| 所有数据读零 | 正式 sysmem 是否仍为占位、译码是否命中 | CPU RAM 回读、NICE ICB 返回 |
| RTL 对但门级 X/时序报错 | SDF/单元模型/角/复位撤销/约束匹配 | STA 与 SDF 注释报告，不能关闭检查掩盖 |

## 7. 下一步工作的优先顺序

1. 完成按官方划分的真实 validation 数据数值统计，并明确每样本导出与 RTL 对照覆盖。
2. 解决正式平台、共享 RAM 和完整固件，完成 CPU 发起任务的 SoC 仿真。
3. 在同一冻结工程下完成 150 MHz 合理约束综合、综合网表功能、面积、活动覆盖、功耗/能耗和吞吐。极小正 slack 需说明预算与覆盖；本科不要求额外做布局布线/流片。
4. 有余力再做选做功能或更大性能优化，每次都保持整数等价和同条件对照。
