# v4.5 设计说明

## 整机数据流

```text
外部装载口 ─┐
E203 LSU ───┼─ ICB 有序仲裁 ── 512 KiB 共享 SRAM / 启动与状态寄存器
加速器 DMA ─┘                      │
                                    └─ 描述符 ── 加速器
                         X/W/b 位流 → 解码 → 8×16 MAC → 量化 → Y 位流
```

E203 从 ROM 跳至 ITCM 固件。装载器通过已有端口把每个矩阵的 X、W 和偏置放到共享 SRAM，CPU 写入描述符地址启动计算，再检查忙标志与返回码。DMA 从同一共享 SRAM 读取输入，所有输出写应答收到后才报告完成。启动寄存器为 `0xA0080000`，状态寄存器为 `0xA0080004`。

## 共享 SRAM

v4.4 的 16 个 SRAM bank 共用一组下降沿写寄存器。每条数据线需要驱动多个宏，且读出经过 16 选 1 后才寄存。v4.5 在 [共享 SRAM 控制器](soc/rtl/kwt_shared_sram.sv) 中把寄存器放到每个 bank 的输入和输出侧。

| 边沿 | 动作 |
|---|---|
| 接收上升沿 | ICB 预留一个应答槽，只有选中的 bank 锁存行地址和命令，写命令同时锁存数据与字节掩码 |
| 同拍下降沿 | 选中的 bank 更新该宏的本地引脚 |
| 下一上升沿 | 单口宏执行操作，写请求可把对应槽标为完成 |
| 再下一上升沿 | 本地寄存宏的读出 |
| 第三个上升沿 | 用随请求传递的 one-hot bank 标签选择数据，完成该读请求的应答槽 |

槽位按请求进入顺序分配和释放。较新的写可以先完成，接口会等待队首，因此连续读写、跨 bank 和应答反压仍遵守 ICB 顺序。写请求在实际写入后的下一次应答握手即可退回。DMA 的内部在途上限、读流标签、写计数和总线仲裁额度一起增为 8。每条解码流仍单独控制预留，防止返回数据挤满解包器。外部装载器和 CPU 使用原始接口和测试时序。

## 定时器与 CPU 时钟

源计划生成脚本 [prepare.py](soc/flow/prepare.py) 对校验过的官方 CLINT 源码做两处精确替换。64 位无符号比较拆成四路 16 位比较，把大于和相等结果寄存后合并。MTIP 对比较结果的响应增加一个主时钟周期。64 位计数加一按 16 位分段，低位进位通过全 1 归约得到，计数值仍在原 RTC 事件更新。RISC-V 特权规范允许比较变化稍后反映到 MTIP。 [Machine-Level ISA](https://docs.riscv.org/reference/isa/priv/machine.html)

IFU、EXU、LSU、BIU 与 ITCM/DTCM 控制器及宏使用同一个高速时钟源，移除 CPU 域内相互独立的门控延迟。IFU 的 WFI 停取指和唤醒握手仍走原逻辑。E203 PLL/外部时钟切换保留，测试采用 P6 的外部时钟旁路。取消局部时钟门控会增加空闲时的时钟活动，综合布局与门级回标需单独检查时钟网负载和偏斜。

## IFU 取指与跳转依赖

首轮 160 MHz 映射暴露了从上一条指令寄存器经过 EXU 译码和接收判断，再反馈到取指请求寄存器的路径。新版的指令寄存器腾空后才接收新的取指响应，避免沿 EXU 的同拍接收信号判断能否接收。JALR 需要读取非零通用寄存器时，等待当前指令和 OITF 清空后再取操作数。JAL、条件分支预测、异常冲刷和取指地址保持原平台协议。若旧指令恰好在新响应到达时消费，或 JALR 原可与旧指令重叠，CPU 取指可增加等待；矩阵 DMA 的请求流独立于该路径。

## 数值与宏

描述符格式 `0x00010004` 沿用 v4.3。每个矩阵产生 99×256 个有符号输出，使用冻结的 X/W/b 比例、40 位累加、最近偶数舍入和饱和。输出以既有 Rice 格式写回。内部宏为 64 个 128×16 和 8 个 1,024×16，配合 16 个共享 SRAM bank 及 ITCM/DTCM 的 16 个宏，整机共 104 个 SRAM 宏。
