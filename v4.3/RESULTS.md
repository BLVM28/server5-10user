# v4.3 结果、代价与适用条件

发布工作点为 **150 MHz**。本轮保留 v4.2 全部量化参数，改用四路 Rice 码流、8×16 阵列和单在途 ICB 交接。下列吞吐按接受 NICE 至输出写回应答全部结束计时；一个 task 是完整 Dense1 矩阵，不是一个语音词。

| 指标 | v4.2 | v4.3 |
|---|---:|---:|
| 同公共 SRAM 端点，固定 12 任务拍数 | 712,077 | **193,356** |
| 同端点，150 MHz tasks/s | 2,527.82 | **9,309.25** |
| 完整核综合面积 mm² | 0.397244 | **1.043554** |
| 局部 SRAM 宏数/容量 | 40 / 24 KiB | 72 / 32 KiB |
| 600 样本最差单层汇总 NRMSE | 0.14181% | **0.14181%** |
| SS 第 0 层平均功率 mW | 28.503 | **91.915** |
| 同任务名义活动时长 μs | 395.593 | 106.560 |
| 同任务能量 μJ | 11.276 | **9.794** |

同端点固定组吞吐为上版的 **3.683 倍**；面积为 **2.627 倍**，增加 0.646310 mm²，但仍只占 2.25 mm² 预算的约 46.4%。平均功率为 3.225 倍；任务能量降低 **13.14%**。这些功率/能量只代表该输入和 SS 子系统窗口，不能外推全部输入或整机。

## 150 MHz 吞吐和总线条件

同一个 32 位端口、单在途限制，旧版和本版都接未经修改的公共 E203 sirv_sram_icb_ctrl 与同步 RAM 功能端点。它支持一拍应答和旧应答/新命令同拍交接；本版的收益主要来自利用该能力以及并行编解码。单纯增加 MAC、沿用原来长等待端点，不能得到这个提升。

12 类代表语音共 144 次任务合计 **2,361,813 拍，9,145.52 tasks/s**；逐任务最慢 17,452 拍，即 8,595.00 tasks/s。高熵合成 base 的最慢单任务为 20,362 拍，仍约 7,366.66 tasks/s。此处一拍行为端点的 worst 组与公共控制器实测的 193,356 拍逐层完全相等。

旧随机长等待条件下，144 次任务为 **1,903.53 tasks/s**；固定组为 2,020.57，上版原记录为 2,028.51，略退约 0.39%。四路头部/对齐增加少量传输，慢总线时该代价无法隐藏。固定 12 任务共 134,728 笔 ICB，而 v4.2 原格式是 130,854。不能把 9,309 与旧版随机等待的 2,028 直接相除当架构提升。

正式 5,000 tasks/s 的预算是每任务总计 30,000 拍；固定组核内平均约 16,113 拍，名义上还有约 13,887 拍/任务给额外调度。但若正式 RAM 产生长等待，或 CPU 现场对动态 X 编码和搬运，这些成本必须重新计入，不能直接宣称整机一定超过 5,000。

## 精度和功能证据

本轮重新运行 600 样本：550 个不同的验证 WAV 加 50 次相同全零静音，来自冻结的分层抽样；不是官方完整测试集。检查 162 个 checkpoint 张量、上游预处理和原始模型 logits 重放，比较 7,200 张 Dense1。最差单层汇总 NRMSE=0.1418107%，最差单样本单层=0.1938524%，超过 3% 的比较为 0。训练-only 33 WAV 标定 profile 未重新调节。

四路传输的数学与 v4.2 一致；NumPy 和 Python3.6 标准库两种独立生成器的 1,400 个向量逐字哈希一致。服务器 30 套完整场景、每套29场景及25码流保护全部通过；本地公共控制器完整测试也通过。另有64组独立点积极值/气泡/归并测试，336组C编码帧及12组实际RTL输出解码，RV32IMAC指令检查和公共E203 wrapper连接检查。门级两角均实际计算一张完整矩阵，不是只检查SDF注释。

这些证据证明已测范围内的 Dense1 运算和接口；尚未运行含量化替换后全部 KWT 层的整网词分类准确率，也未完成真实 E203 启动固件验收。

## 150 MHz、面积与功耗

SS 建立/保持 +1.466715/+0.161594 ns，FF +3.567728/+0.080024 ns，全部报告违例为零。180 MHz 两角扫点也通过，但发布仍用150 MHz；SS建立余量约周期22%，为后续物理设计留空间。完整宏计数、ECO等价与网表身份见 [服务器报告](SERVER_RESULTS.md)。

PrimeTime PX 的 SS 0.99 V/125°C 结果：动态 91.365 mW、漏电 0.550 mW、总计 91.915 mW；内存组约10.9 mW，寄存器时钟引脚内部功率组约42.9 mW。所有已报告357,990条网从真实SDF任务VCD标注，default/unannotated均为0；SRAM功耗有真实库模型，没有当作零。

这是前布局加速器估算，**未设置线负载模型，也无SPEF/时钟树，排除CPU、共享512KiB RAM和互连**；SS并不自动等于最坏功耗PVT。能量用实测周期×名义150 MHz时长×平均功率，存在仿真时间量化及窗口边界的微小差异。不能用本数字承诺芯片总功耗或所有输入能量。

## 交付与剩余事项

正式文件在 rtl/、tb/、integration/、py/ 和 server_eda/；五个 ZIP 分开存放 packages/，每个目录均有 README。按 [手册](SERVER_GUIDE.md) 运行 make compile/run/timing/report/waves/verdi；修改RTL必须重综合再验证网表哈希。

仍需队伍落实正式共享RAM及地址、E203调度与动态X编码的计时、整机CPU/互连/RAM功耗；若进行物理设计，还要完成CTS/布线/寄生后检查。本轮没有修改公共目录、旧版RTL或旧正式包。
