# 给平台/任务3负责人的具体整改

## 输入版本

采用本包rtl.f和interface/当前头文件，格式`0x10005`。14个活动RTL文件，其中writer和NICE格式校验改动；其余12个RTL逐字节保留r8。不要继续混入旧kwt_rice_pack、旧compressed Y检查器或旧firmware.hex。

## 装载旁路——未代改

直接证据位于 `../依据/P6_只读证据/kwt_e203_soc_top.v:149–176`：u_shared_arbiter接收`{load_cmd_valid,sysmem_icb_cmd_valid}`；TB第39–41行接专用load端口、第172行起发装载请求。答复第16问明确禁止这种接法。仍保留ICB握手、32位宽、共享SRAM和CPU访问并不能让此旁路合法。

平台负责人须撤销该旁路，用平台原有合法入口完成真实传输，再由System Bus到共享SRAM。可采用CPU通过原平台接口搬运，或在平台支持范围内接入System Bus的DMA。**不要把`load_*`改名为`sysmem_*`，不要force内部总线、直接层级写共享数组或新增独立SRAM写口来伪装修复。** 若外部入口/加载源的具体归属尚不明确，拿实际平台原图和接口定义确认；不能凭本报告虚构端口。

更新固件/测试台：输入和W/b从本任务装载开始计时，覆盖数据传输、CPU调度、等待、NICE计算直至最后结果写应答。任务前清任务数据和参数缓存，初始化不能暗中预置本任务参数；测试间reset时间按规则排除。TB主机读文件和一次性格式转换可排除。调试用组件TB的直接初始化仅用于功能测试。

## 新输出接法

保留NICE自带32位访存→LSU/BIU→System Bus路径。Y_base仍按64KiB保留区检查，成功结果位于前12672字。对每个row/col按`Y_base+2*(row*256+col)`读取signed16，再除以2048；默认低半字先。写顺序为列组顺序，但存储位置为行优先。总共152064字/12任务。

用新的`kwt_make_streams_descriptor`重编main.c，原main.c中的同名调用可复用；原C读取入口已变为固定拆字。修改TB的compressed槽位/字数检查为逐字完整矩阵检查。NICE错误可能触发E203异常，错误路径需按平台trap约定验证。提交时一起冻结RTL、平台define、固件源码/镜像与工具链版本。

## 综合——本轮只交问题

原r8同映射150MHz整机setup/hold为+0.109991/−0.092604ns；160MHz为−0.306675/−0.092604ns。原加速器自身150MHz为+0.546274/+0.011303ns、160MHz为+0.253513/+0.011303ns。均是**旧压缩writer**的历史值。

1. 按声明的合理库/PVT/RC/负载/不确定度重新综合本修改版。答复第4问允许合理工艺条件，仍须150MHz整个声明工程满足时序。
2. 原共享SRAM bank8写数据保持违例、160MHz IFU建立违例、UART TX FIFO的24个未约束端点，由平台负责解决/解释并给完整覆盖报告。原最坏电气规则记录115条slew、2条cap也要复核。不能用false_path/multicycle掩盖正常功能路径。
3. 保留指定SRAM宏真实时序/面积/功耗，不把功能模型用于综合。新增面积包含接口和内部宏；复用E203/共享SRAM单列，避免漏计/重复。
4. 重新测正式周期与覆盖完整的VCD/SAIF、功耗/能耗；旧58547写字已变152064字/12任务。不能继续报告旧时延或从单周期SRAM组件模型换算正式吞吐。

本轮未做综合或门级网表，符合用户“综合有问题只指出”的范围。修改版没有可报告的150/160MHz最差STA裕量。

## 联合验收最低条件

- 指定12任务从合法装载入口运行，每任务25344个元素与当前软件模型逐位一致；每任务NRMSE≤3%。
- 逐项证明装载、读、写都经过平台规定通路；计时包含上述完整窗口。
- 150MHz完整约束下setup/hold/电气规则及覆盖通过，新增面积≤2.25mm²；同一配置出报告。
- 通用WAV/任务清单适配、工具依赖和命令可在EDA平台复现；不能只支持当前固定hex。
