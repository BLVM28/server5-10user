# v4 实测 · 150 MHz 的冷任务吞吐

**目标定义。** 一个任务是一次 99×64×256 Dense1，含偏置、量化与整张写回。计时从 NICE 指令握手到第一次完成响应，覆盖描述符读取、数据和层参数从共享 RAM 冷装载、全部等待和写应答。不把测试台响应背压或任务间复位计入。一次计算从头加载测试窗口。完整 E203 的指令调度耗时另属整机测试。

## 三个同条件实测点

| 版本 / 输出格式 | 12 次 NICE 周期 | 150 MHz 耗时 | 吞吐，tasks/s |
|---|---:|---:|---:|
| v3.1 / 原始 | 3,455,514 | 23.037 ms | 520.91 |
| v4 / 原始 | 2,010,320 | 13.402 ms | 895.38 |
| v4 / 紧凑 | **1,568,392** | **10.456 ms** | **1,147.67** |

三行并行、分离 DMA 与独立页使原格式也显著提速。同一 v4 硬件切到紧凑格式，12 个任务的实际输出写数从 152,064 减为 83,402，减少 **45.15%**。两种格式硬件都执行 12×25,344 个完整 64 项点积，结果逐位相同。v3.1 周期来自其冻结源的独立复跑，使用同一随机 BFM 和同一握手计时，比旧报告中只计 core_cycles 的数据更适合直接比较。[12 层周期和写字数](results/functional.json)

这批逐层 worst 输入在自选调试集中按数值误差择样，不是故意选择最慢或最快的总线数据。按 1000 tasks/s 的 12 任务门槛共 1,800,000 拍，本批测得的 NICE 时间还有 231,608 拍可用于其它开销。官方的冻结后样本、共享 RAM 和真实 E203 调度可能改变结果。

## 准确度与解码

从 14 套物理 HEX 读回 X/W/b，用原始整数金模独立重算 168 个矩阵，全部 **4,257,792 个 40 位累加值、4,257,792 个 int16 输出和 168 个饱和统计**与原始期望一致。C/Python 解码和 RTL 均使用这些原始期望作比较。[整数重算](results/numeric.json)

- 量化格式、乘法、40 位累加、偏置、最近偶数舍入和饱和的语义继承 v3.1。编码器的输入是已经得到的 signed16 Y。若差值超出窄码范围就在 RTL 写原始绝对值。13 套真实激活中的两种输出格式都比较全部累加和最终元素。数据长度改变时，读取/输出缓冲区边界也按新格式检查。
- C 消费端逐元素核对了 336 个软件参考帧，另直接读取 12 层 RTL 导出的真实总线内存。Python 解码器和 C 解码器均恢复原始黄金结果；总计 348 个 C 帧。另有 4,096 项硬件边界与随机编码测试。交付的原始和紧凑 RV32 驱动均已交叉编译、反汇编核对。[软件验证](results/codec.json) · [RV32 驱动](results/driver.json)
- 该整数格式已有自选 600 例软件浮点评估，最大逐层汇总 NRMSE 为 **0.03891237%**，样本含 550 个不同 WAV 和 50 次零静音。v4 的证据是 RTL 与整数参考逐位一致，以及编码/解码未增加误差。未将历史软件数值写成 v4 官方 600 例 RTL 或端到端分类结果。[原评估报告](../v2/validation_real_speech_20261102/README.md)

## 面积、临界路径和时钟

完整 kwt_nice_core（含 NICE、ICB 和 41 个内部 SRAM 宏）在 SMIC 40 nm 前端综合中的总面积为 **319,783.511825 µm²，即 0.319784 mm²**。宏为 148,587.932373 µm²（46.47%），标准单元为 171,195.579452 µm²。v3.1 的同口径总面积为 155,089.240090 µm²，新版增加 **106.19%**。按 worst 成对任务的同频吞吐增长 **120.32%**，该点单位面积吞吐增加约 **6.85%**。宏容量从 16 增到 20.75 KiB。内部宏已计入一次；正式 SoC 中新增的顶层接口面积仍需并入赛题 2.25 mm² 的预算。[工艺记录](results/ppa.json) · [赛题印刷页 12](../01_核心参考/赛题介绍_原文.txt)

综合约束优化目标为 5.8 ns。资格测试对同一份完整网表分别使用 SS 0.99 V/125 °C 和 FF 1.21 V/−40 °C、时钟不确定度 0.100 ns、I/O 最大/最小延迟 1.000/0.100 ns 和 0.002852 pF 输出负载。各项成绩采用比赛 **150 MHz**；前端通过的更高频点单列。慢角最差建立路径为 DMA 已采样 Y 寄存器至无损差分寄存器。150 MHz SS 的 55,164 个时序检查有 47,889 个满足、7,275 个未测、0 个违例。未测项可追到服务器 coverage.rpt 与 untested.rpt。

初次映射发现 320 个仿真观察输出导致最小负载违例。修订 RTL 后，剩余一处 U2216/ZN 超过慢角最大电容 0.002746 pF。使用同功能 CLKINV5 替换 CLKINV4，核对全部网表语句仅该引用变化，继续采用原约束重跑时序。[映射调整](server_eda/resize_plan.txt) · [首轮证据](results/first_candidate.json)
